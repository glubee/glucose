# 리포트 "하루 이야기"와 생활 안내 카드 개편 계획

작성: 2026-10-28 · 상태: **계획(결정 대기 4건)** · 관련: `report-narration.md`, `guidance-cards.md`, `food-observations.md`,
Downloads의 `medical-info-policy.md`(정책 초안)

## 0. 요약

- **문제 1:** 일일·주간 요약이 "섭취 기록 3건, 인슐린 2건…" 같은 상태 줄 목록이라 읽히지 않는다. 사용자는 "언제 무엇을 먹고, 언제 인슐린을 맞았고, 그 뒤 혈당이 어떻게 움직였는지"를 한 문단으로 원한다.
- **문제 2:** 안내 카드 17장이 "그래프 읽는 법" 같은 앱 사용 설명 위주다. 기록을 보고 **생활에서 바꿔볼 만한 점**을 출처와 함께 알려주는 카드가 필요하다(예: 저혈당 때 초콜릿을 먹었다면 "지방이 많은 음식은 흡수가 느리다").
- **방향:** 서버가 사실(시각·음식·단위·읽힌 값)만으로 문장을 조립하는 **하루 이야기**를 기본 요약으로 바꾸고, 카드는 **기록에 반응하는 생활 안내**로 다시 짠다. 문장과 카드 모두 원인 단정·용량 조언·진단은 하지 않는다.

## 1. 하루 이야기 (일일·주간 요약)

### 1-1. 보여줄 모습 (예시)

> 오늘은 8시 10분에 현미밥 1공기와 계란말이 1접시를 먹었고, 8시에 노보래피드 4단위를 기록했어요.
> 먹기 전 105였던 혈당은 1시간 40분 뒤 168로 가장 높았고, 11시쯤 120으로 내려왔어요.
> 13시 40분에는 혈당이 61까지 읽혀 포도당 캔디 3개와 오렌지 주스를 먹었어요. 그 뒤 2시간 동안 180을 넘는 값은 없었어요.
> 저녁 무렵 18시부터 21시까지는 그래프가 비어 있어 이 구간은 알 수 없어요.

주간 예시:

> 이번 주는 6일 그래프가 있었고, 아침은 주로 현미밥과 계란말이(4번)였어요. 그 아침 뒤 가장 높았던 값은 150~172 사이였어요.
> 70 미만으로 읽힌 날은 2일이었고, 두 번 모두 포도당 캔디로 대응했어요. 수요일 저녁 맥주 기록 뒤 새벽에 낮은 값이 있었어요.

### 1-2. 규칙

| 규칙 | 내용 |
|---|---|
| 문장 재료 | 기록(시각·상황·음식 이름·인슐린 단위·종류)과 그래프에서 읽힌 값만. 이미 서버에 있는 `FoodObservationAnalyzer`의 기준값(baseline)·최고값(peak)·구간 끝 값(end)을 그대로 쓴다. |
| 시간 순서 | 하루를 시간순 "장면"으로 나눈다: 식사·간식 / 저혈당 대응 / 술 / 인슐린 / 그래프 빈 구간. |
| 숫자 | 모두 서버가 계산. 문장 안 숫자는 근거(사실 ID)와 연결해 앱에서 "근거 보기"로 확인. |
| 표현 | **시간 순 변화만** 쓴다: "먹은 뒤 1시간 40분 동안 105에서 168까지 올랐어요." **원인 단정 금지**: "짜장면 때문에 올랐어요", "인슐린이 부족했어요" ✗. 결정 1 참고. |
| 겹침 | 분석 창이 다른 기록과 겹치면 "다른 기록과 겹쳐 한 기록만의 변화로 보기 어려워요"를 붙인다(기존 규칙). |
| 빈 구간 | 끊긴 구간은 보간하지 않고 "비어 있어 알 수 없어요"로 쓴다. |
| 길이 | 일일 3~6문장, 주간 3~5문장. 장면이 많으면 저혈당 → 식사 → 나머지 순으로 줄인다. |
| AI | 1단계는 **AI 없이 템플릿**(결과가 항상 같고 테스트 가능). 2단계에서 원하면 기존 문장화(사실 ID만 보내고 서버가 렌더링)로 말투만 고르게 한다. 결정 4. |

### 1-3. 작업

1. 서버 `DailyStoryBuilder`/`WeeklyStoryBuilder`: 장면 추출 + 템플릿 문장 + 사실 ID. 일일 응답에 `story: { text, facts[] }` 추가(기존 `summary`는 근거 보기로 이동).
2. 앱 리포트 맨 위 "기록 요약" 카드를 한 문단으로. 아래 "근거 보기"에 기존 줄 목록과 수치.
3. 테스트: 장면별 문장, 금지 표현 목록(`ReportSummaryBuilderTest`의 FORBIDDEN 확장: "때문", "덕분", "부족", "과다" 등), 빈 구간·겹침.

## 2. 생활 안내 카드

### 2-1. 원칙 (정책 초안 유지 + 보강)

- 미리 쓰고 **의료인이 검토한 문구만**. AI가 만들지 않는다. 카드 선택은 코드 규칙(기록 트리거)이 한다.
- **일반 지침**만: 학회·공공기관 지침을 풀어 쓴다. 인슐린 용량·투약 변경·진단은 없다.
- 개인 기록에 반응하되 문구는 "이렇게 하세요"가 아니라 "지침에서는 ~를 권해요 / ~라고 알려져 있어요" + "의료진이 정해준 방법이 있으면 그 방법을 먼저 따르세요".
- 출처는 기관·문서·연도를 저장하고 화면에 표시. 원문 대조일(`verified_at`)을 기록.
- 한 리포트에 최대 3장. 같은 카드는 "이미 알아요"로 4주 숨김(저혈당 대처 카드는 숨기지 않음).

### 2-2. 카드 후보 (기록 트리거)

출처 약어: ADA = 미국당뇨병학회 Standards of Care(최신판 6장 혈당 목표·저혈당), KDA = 대한당뇨병학회 진료지침, KDCA = 질병관리청 국가건강정보포털. **모든 내용은 원문 대조 전 초안이다.**

| 코드 | 트리거(코드 규칙) | 핵심 내용(초안) | 출처 |
|---|---|---|---|
| G01 저혈당 대응엔 빠른 당 | 저혈당 대응 기록의 음식에 `HIGH_FAT` 태그(초콜릿·과자 등) | 지방이 많은 음식은 당 흡수를 늦춰 저혈당 대응엔 포도당·주스·일반 탄산음료처럼 빨리 흡수되는 당이 권장돼요 | ADA, KDCA |
| G02 15-15 원칙 | 저혈당 대응 기록 또는 70 미만 값 | 빠른 당 15g 정도 → 15분 뒤 다시 확인 → 회복될 때까지 반복이 일반 지침이에요. 의료진이 정해준 방법이 먼저예요 | ADA, KDCA |
| G03 대응 뒤 다시 높아짐 | 처치 뒤 분석 창 안 180 초과(반동) | 한 번에 많이 먹기보다 15분 기다렸다 다시 확인하는 방법이 지침에 있어요(양 조언 아님) | ADA |
| G04 밤 저혈당 | 0~6시 70 미만 | 자기 전 혈당 확인과 밤 저혈당 경향은 의료진과 상의하라는 내용 | ADA, KDCA |
| G05 술 마신 날 | 술 기록 | 빈속 음주 피하기, 음식과 함께, 자기 전·다음 날 아침 확인 | ADA |
| G06 같은 식사 뒤 높은 값 반복 | 같은 음식 조합 2회 이상 + 매번 최고값 180 초과 | 식사 구성(채소·단백질 함께, 정제 탄수화물 양) 일반 정보 + 의료진·영양사 상담 권유 | KDA 식사요법, KDCA |
| G07 늦은 밤 간식 | 22시 이후 간식 기록 반복 | 늦은 간식과 다음 날 아침 혈당에 관한 일반 정보 | KDA |
| G08 기록이 빈 날 | 그래프 빈 구간이 하루의 30% 이상 | 센서 연결·스캔 습관 안내(앱 안내, 의학 근거 아님) | APP_GUIDE |

- 지금 카드 중 "그래프 읽는 법·센서와 손끝 혈당 차이" 같은 설명형은 리뷰 탭에서 **도움말**로 옮긴다.
- 응급 카드(119)는 유지한다.

### 2-3. 작업

1. 지침 원문 확보·대조(ADA 최신판 6장, KDA 진료지침 저혈당·식사요법, KDCA 저혈당·음주): 문장별 근거 위치 기록.
2. 카드 초안 작성 → **의료인 검토**(결정 3) → `approved=true`. 검토 전 카드는 개발 빌드에서만 "검토 전" 표시와 함께.
3. 트리거 구현: 음식 태그(`HIGH_FAT` 등은 `food_catalog`에 이미 있음), 반동·밤 저혈당·술은 기존 판정 재사용, G06·G07은 주간 집계 추가.
4. 앱: 일일 리포트 카드 자리 + 리뷰 탭 "이번 주 생활 안내"(그 주 트리거된 카드 모음).

## 3. 결정이 필요한 것

| # | 결정 | 추천 |
|---|---|---|
| 1 | 문장에 "영향" 표현을 어디까지 쓸지 | **시간 순 변화만**("먹은 뒤 ~까지 올랐어요"). "때문에/덕분에"는 쓰지 않음. 의료기기 소프트웨어로 분류될 위험(정책 초안 6장)을 피한다. |
| 2 | 일반 지침의 숫자(15g, 15분)를 카드에 쓸지 | **쓴다**(정책 초안 C05와 같음). 개인 맞춤 양은 쓰지 않는다. |
| 3 | 의료인 검토자 | 교내 의대·간호대 교수 또는 당뇨 교육 간호사 1명 확보. 검토 전에는 운영 노출 금지. |
| 4 | AI 문장 다듬기 | 1단계는 템플릿만. 품질이 아쉬우면 2단계에서 기존 사실-ID 방식으로. |
