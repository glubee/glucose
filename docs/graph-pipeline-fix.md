# 그래프 분석 경로 보완

## 재현

2026-10-28 사용자가 원본과 앱의 그래프 불일치 및 새 업로드 실패를 보고했다.
앱에 표시된 한 날짜의 평균·최저·최고·관측 수 네 항목이 보존된 1.0.0 파서의 잘못된 결과와 모두 일치했다.
구버전은 왼쪽 글자와 하단 시간축을 혈당 영역에 포함해 좌표를 잘못 보정했다.
현재 소스는 7개 수평 격자선으로 축을 확인하지만, 운영 실행 이미지와 저장 결과가 그 소스와 일치하는지 확인할 경로가 부족했다.

개인 원본과 수치는 저장소에 넣지 않는다. 개인 이미지 재현 결과는 로컬 `backend/build/graph-debug/`에만 둔다.
CSV를 인식·날짜 판별·보정 입력으로 사용하지 않는다.

## 변경

- ML 1.1.5: 기존 곡선 추출 수학은 유지한다. 실제 실행 버전을 health에 표시하고 날짜/축/OCR 실행 오류를 구분한다.
- 백엔드: 최소 지원 1.1.4 미만 또는 미확인 분석기 응답은 저장 전에 거절한다.
  해당 검증 실패는 작업의 FAILED 상태까지 롤백시키지 않도록 쓰기 전 checked exception으로 전달한다.
- 이전 구버전 저장 결과는 차트 시계열 및 모든 리포트 집계에서 제외한다.
- 소유자 인증 후 저장된 원본을 다시 분석하는 API를 추가한다. 처리 중인 작업은 중복 생성하지 않는다.
- 같은 업로드의 시간 슬롯을 교체할 때 DELETE를 먼저 flush해 유일성 충돌을 막는다.
  기존 값 삭제와 새 값 저장은 동일 트랜잭션이라 저장 실패 시 기존 값도 복원된다.
- 앱: 재분석 안내와 실행/폴링, 실패 이미지 재시도 시 저장된 원본 재사용, 단계별 오류 안내를 추가한다.
- 앱 차트: 원본과 같은 50~350 축과 3시간 간격을 사용한다. 결측 구간을 잇지 않는 규칙은 유지한다.

## 검증

- 실제 Linux/Tesseract kor+eng에서 첨부 원본 2장과 기존 개인 원본 33장을 HTTP API로 처리한다.
  날짜 주입 없이 실제 OCR·전처리·곡선 추출을 실행한다. 자세한 수치 및 결과는 로컬 비공개 산출물에만 보존한다.
- `test_native_graph_pipeline.py`: 합성 그래프의 실제 날짜 OCR부터 96개 수치 및 공백을 HTTP로 검증한다.
  Tesseract가 없으면 명시적으로 skip하며 대체 OCR 결과를 네이티브 OCR 성공으로 세지 않는다.
- 백엔드 통합 테스트: 구버전 성공 응답 거부, 기존 결과 차단, 재분석·중복 요청·소유자 인증·실패 시 보존을 검증한다.
- `GRAPH_PIPELINE_SMOKE_URL=http://127.0.0.1:<로컬 ML 포트>`를 지정하면 합성 이미지를 실제 S3 업로드 경로로
  넣고 실제 네이티브 ML HTTP 서버로 전달해 96칸의 DB 저장·조회·일일 리포트까지 검증한다.
- 최종 로컬 실행: 그래프/리포트 Java 테스트 104개 통과, 실제 AI 호출용 별도 테스트 1개 skip.
  파서/API/네이티브 OCR Python 테스트 47개 통과. 위 개인 원본 35장 모두 200 응답이며 화면에서 옮긴 날짜와도 일치했다.
- Windows에는 Xcode가 없어 iOS 빌드/기기 실행은 별도 확인이 필요하다.

## 운영 배포에 필요한 후속 변경안 — 아직 적용하지 않음

현재 워크플로는 현재 저장소 소유자 이름으로 이미지를 빌드하지만, 운영 서버의 Compose 파일은 저장소에 없다.
저장소 조직 이름이 이동한 이력이 있어 서버가 어느 registry/태그를 실행하는지 확인해야 한다.
현재 실행 중인 운영 이미지의 버전은 이 로컬 검증만으로 확정하지 않는다.

다음 운영 변경은 별도 승인 후 적용한다. 자동 승인 검토가 배포 워크플로 변경을 거절하여 아직 수정/실행하지 않았다.

1. GitHub 테스트 단계에 네이티브 Tesseract kor+eng를 설치해 실제 OCR 회귀 테스트를 실행한다.
2. 빌드한 이미지의 정확한 저장소 주소와 커밋 태그를 배포 단계에 전달한다.
3. Compose override로 이번 커밋의 app/ml-service 이미지를 선택한다. 이름이 이동하기 전의 latest를 그대로 쓰지 않게 한다.
4. 재시작 후 실제 컨테이너 이미지 ID가 해당 커밋의 이미지와 같은지 확인한다.
5. 실제 ML health의 graph_parser_version과 모듈 버전, 백엔드 health를 확인한 뒤 배포 성공으로 처리한다.

예정된 override 형식(실제 커밋으로 채운 뒤 검토):

```yaml
services:
  app:
    image: ghcr.io/glubee/glucose-app:<이번에 빌드한 커밋>
  ml-service:
    image: ghcr.io/glubee/glucose-ml:<이번에 빌드한 커밋>
```

운영 반영 후 앱에서 저장된 그래프를 재분석하고 원본과 다시 대조해야 실제 사용자 경로 검증이 끝난다.
