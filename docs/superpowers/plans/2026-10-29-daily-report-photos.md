# 일일 리포트·그래프 3단계 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. User approved phase 3 directly.

**Goal:** 직선·결측 구간 규칙, 요약 우선 배치, 가까운 사진 묶기·곡선 부근 표시, 사진 확대와 기존 기록 상세 연결.
**Architecture:** GlucoseCurve/ChartPhotoGroup/PhotoMarkerLayout에서 표시용 위치와 묶음을 계산한다. 사진은 관측된 구간에만 붙이고 없는 시각은 아래 사진 줄에 표시한다. 실제 기록 상세는 기존 조회 API에서 일치하는 기록을 확인한 뒤 기존 편집 화면을 재사용한다.
**Tech Stack:** SwiftUI, Swift Charts, XCTest/XCUITest, iOS 17+.
**Spec:** Downloads/ux-improvements-2026-10-29.md 1-5·1-6·1-7 및 사용자 승인 3단계.

## Global Constraints
- 읽힌 값과 서버 요약 문장은 바꾸지 않는다. 표시용 선 위치를 실제 관측 혈당값으로 보여주거나 저장하지 않는다.
- MISSING/null 및 관측 사이 15분 초과는 다른 선 구간이다. 일간·주간 공통 선은 linear를 쓴다.
- 30분 묶음은 첫 사진부터 최대 30분이며, 연쇄적으로 긴 구간을 한 묶음으로 만들지 않는다.
- 홈은 아이콘 유지. 일일·확대 그래프는 사진과 아래 사진 기록 줄을 제공한다.
- 서버 변경 없음. 리포트에 record ID가 없으므로 기존 /v1/intakes cursor 조회로 시각·photo_id·context를 대조한다. 모호하면 임의로 수정할 기록을 선택하지 않는다.
- 실제 사진 URL·토큰·사용자 자료를 로그/커밋에 넣지 않는다. 샘플은 그림으로 대체하고 기록 편집은 차단한다.

## Review Focus
- 선택 시각이 결측/경계/하루 밖이면 근처 관측을 그 시각의 값처럼 표시하지 않는다.
- 같은 시각 사진·인슐린 또는 동일 사진 중복 기록도 마커/목록에서 사라지지 않는다.
- 사진 밀집·차트 경계·확대/스크롤 중 버튼이 겹치거나 화면 밖에 남지 않는다.
- 기록 조회의 날짜 경계·동일 시각 중복·반복 cursor·취소·실패에서 잘못된 상세를 편집하지 않는다.
- 사진/날짜를 빠르게 바꾸거나 기록을 수정·삭제해도 이전 응답/사진 화면이 남지 않는다.

## 구현 결정과 한계
- 기존 전용 clone과 기능 브랜치를 유지했다. Xcode 경로가 유지되는 이점이 있으며, 단계 안의 변경은 한 커밋으로 묶어 부분 되돌리기의 세분성은 줄었다.
- 서버 계약은 변경하지 않았다. 시각·사진 ID·입력 분류가 모두 맞는 실제 기록을 조회한다. 여러 건이면 임의로 고르지 않는다. 최대 20페이지(2,000건) 안에 검색을 완료하지 못하면 전체 기록으로 안내하므로 아주 오래된 기록은 추가 탐색이 필요할 수 있다.
- 사진 위치 계산은 관측이 이어진 구간의 직선 위에만 사용한다. 선택 수치에는 실제 관측값과 그 관측 시각만 표시한다. 잘못 사용하면 새 측정값으로 오해할 수 있어 표시용 위치를 수치로 노출하지 않는다.
- 사진이 밀집해 차트 안에 배치할 수 없으면 아래 사진 줄에서 연다. 모든 사진을 유지하지만 일부 사진은 아래 줄을 이용해야 한다.
- 독립 리뷰: Critical/Minor 없음, Important 1건(재분석 상태의 사진 진입점 누락). 실행 확인을 보류했던 확대→하루 복귀 위치도 테스트로 확인해 추가 문제로 재현했다. 두 문제 모두 회귀 테스트 실패를 확인한 후 수정했다.
- 실제 서버의 로그인 계정·사진 보기 URL·기록 수정/삭제 통합 동작, 실물 iPhone 및 iOS 17 런타임 검증은 별도 확인이 필요하다. 시뮬레이터의 예시는 생성한 도형 사진이며 저장·수정·재분석은 차단한다.
