# 4단계: 홈 타임라인·기록 탭

사용자 승인: 기존 단계별 계획의 다음 단계에 대해 “알려주고 진행해 바로”라고 요청했다. 추가 선택 질문 없이 기존 SwiftUI 화면과 API를 재사용한다.

## 목표와 범위
- 홈의 오늘 흐름 아래에 오늘 저장한 음식·인슐린과 기기의 확인 대기 사진을 시간 오름차순으로 표시한다. 사진 썸네일, 시각, 음식 이름·양, 분류와 확인 필요 상태를 보여준다.
- 저장된 항목은 기존 RecordDetailView, 대기 사진은 기존 PendingPhotoDetailView로 연결한다. 음식과 인슐린 수정·삭제가 홈·목록·리포트를 갱신한다.
- 새로 저장하거나 찍은 오늘 항목으로 돌아오면 해당 행까지 이동하고 약 2초 강조한다. 과거 날짜 기록은 오늘 목록에 억지로 넣지 않는다.
- 기록이 없으면 음식 찍기와 글로 남기기 버튼을 제공한다. 실패·부분 로드에서는 빈 상태로 단정하지 않고 재시도를 제공한다.
- 리뷰 탭을 ‘기록’(list.bullet.rectangle)으로 바꾼다. 최신 날짜부터 목록을 보여주고 전체 / 음식 / 인슐린 / 대응 필터를 제공한다. 음식은 식사·간식, 대응은 사용자가 지정한 저혈당 처치·음주다. 앱이 대응 여부를 새로 판단하지 않는다.
- 리포트의 전체 기록 시트도 같은 목록과 필터를 쓴다. 탭에는 닫기 버튼을 두지 않고 시트에는 유지한다.
- 기존 안내문 전체 목록을 설정의 ‘안내 모아보기’로 연결한다. 일일·주간 리포트의 안내는 유지한다.

## 구현 선택
기존 두 API의 cursor 병합 목록을 확장한다. 새 서버 API나 별도 로컬 기록 사본은 만들지 않는다. 홈은 오늘 경계까지 필요한 페이지를 조회하고 기기의 사진 목록을 합친다. 필터를 먼저 제한한 후 화면 분량을 채워 첫 페이지에 일치 항목이 없다고 빈 목록을 표시하지 않는다.

홈과 기록 탭을 별도 저장소로 만드는 방법은 수정 후 불일치가 생기기 쉬워 채택하지 않았다. 전체 기록을 홈에 그대로 표시하는 방법은 과거 기록으로 홈이 길어져 채택하지 않았다.

## 제약·실패 방지
- iOS 17+, 현재 디자인 체계와 기존 API 유지. 서버·동기화·진행 칸·월간 기능은 이후 단계다.
- 서버의 원시 기록을 사용하고 분석 에피소드 건수를 음식 기록 건수로 오인하지 않는다.
- 같은 시각 기록은 모두 남긴다. API 스트림별 UUID 중복은 한 번만 표시한다. cursor 반복·취소·이전 요청 응답은 목록을 오염시키지 않는다.
- 오늘은 ReportDay.calendar의 날짜 경계이며 앱 복귀 시 날짜를 갱신한다.
- 저장 성공 응답의 ID로 새 행을 찾는다. 실패하거나 중복 누른 저장은 갱신/강조를 발행하지 않는다.
- 실제 자료·보기 URL·자격 증명은 로그/커밋 금지. UI 검증은 별도 메모리 저장소와 임시 합성 사진으로 수행하고 실제 API를 호출하지 않는다.
- 물리 마우스·트랙패드 스크롤의 기존 확인 한계와 실제 서버 인증·실기기 검증은 구분해서 보고한다.
