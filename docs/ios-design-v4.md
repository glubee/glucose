### 글꼴·간격·모양
- 글꼴: 시스템(SF Pro / Apple SD Gothic Neo). 홈·말풍선의 굵은 둥근 제목은 **Dynamic Type 스타일**로 대응(`.title2.bold()` 등). 커스텀 폰트는 라이선스 확인 전까지 쓰지 않는다.
- 화면 좌우 여백 20, 카드 안 여백 16, 카드 간격 12.
- 라운드: 카드 16, 버튼(캡슐) 전체 둥글게, 칩 캡슐, 시트 상단 24.
- 주 버튼: 높이 52, `brand` 배경 + `textPrimary` 글자(흰 글자 금지 — 대비 부족).

### 마스코트(글루비)
- 기존 5동작(인사·기록 보기·빠진 기록·시간 선택·저장 완료 등) + 새 8동작(끄덕이기·고민·엄지·응원·카메라·돋보기·쉬기·꿀단지).
- **개별 PNG(투명 배경, @2x/@3x) 또는 PDF로 다시 내보내 받아야 한다.** 캔버스 캡처에서 잘라 쓰지 않는다.
- 규칙(v4 메모 그대로): 색 필터·과한 확대·회전 금지, 오류·미기록 상태를 성공 표정으로 표현하지 않기.

## 2. 탭 구조
기존 `홈 / 기록 / 리포트 / 설정` → v4 `홈 / 리포트 / 리뷰 / 설정`.
- 기록 목록 탭이 없어진다. 지난 기록 확인·수정은 **리포트 일간 타임라인 → 상세**로 들어간다.
- 리브레 그래프 업로드는 설정의 "혈당 가져오기"로 옮겨진다(→ 개선 제안 2).

## 4. 개선 제안 (v4에서 바꿀 것)
1. **kcal·영양정보 표시 빼기.** 계약상 AI는 "무엇을 몇 개"까지만 내고 영양 숫자는 응답에 없다. 사진 추정 kcal은 오차가 크고, 이 앱의 목적(혈당 변화 확인)과도 거리가 있다. 항목은 `이름 · 개수 단위`로, 합계 카드는 "N가지 음식"으로 바꾼다. 직접 등록의 영양 입력칸도 빼고 이름·단위만 받는다.
2. **혈당 그래프 업로드를 홈에 노출.** 모든 리포트·리뷰가 그래프에 달려 있는데 설정 안에 숨어 있다. 오늘 그래프가 없으면 홈 차트 자리에 "리브레 그래프 올리기" 빈 상태 카드를 둔다.
3. **끊긴 구간은 잇지 않기.** v4 차트(홈·리뷰·리포트)는 매끈한 곡선이다. 실제로는 `MISSING` 구간을 비우고, 점 사이만 직선으로 잇는다(곡선 보간 금지). 기존 `GlucoseDayChart` 규칙 유지.
4. **"글루비의 제안"은 서버 `education_card` 고정 문구만.** "포도당 정제·주스 준비" 같은 문구는 일반 교육 정보로만, 출처와 함께, 의료인 검토 문구로 표시한다. 앱에서 문장을 만들지 않고, 용량·양 추천은 넣지 않는다.
5. **저혈당 처치 기록을 빠르게.** 지금은 음식 기록 → 촬영 → 확인 → 맨 아래 칩에서 "저혈당 대응"을 고른다. 홈 음식 기록 시트에 "저혈당 대응으로 기록" 항목을 추가해 상황을 미리 정하고 들어간다.
6. **탭 바는 기본 `TabView` + 색 토큰.** 떠 있는 캡슐 탭 바는 직접 만들면 접근성·안전 영역 처리가 늘어난다. iOS 기본 탭 바에 brand 색만 입힌다(원하면 나중에 교체).
7. **회색 작은 글씨 대비 확인.** 캡션(`textSecondary`)은 흰 배경에서 4.5:1 이상으로 맞춘다. Dynamic Type 큰 글씨에서 홈 제목과 마스코트가 겹치지 않게 마스코트를 줄이거나 아래로 보낸다.
8. **이름 표시.** 프로필 API가 없으므로 처음엔 이름 없이("오늘의 흐름을 함께 볼까요?") 쓰고, 설정에서 별명을 입력하면 기기에 저장해 쓴다.

## 5. 진행 순서

### A단계 — 지금 API로 가능한 것 (iOS만)
| PR | 브랜치 | 내용 |
|---|---|---|
| D0 | `feat/ios-design-tokens` | `Core/DesignSystem/`: 색 에셋(라이트/다크), 글꼴 스타일, 간격·라운드, 마스코트 에셋 |
| D1 | `feat/ios-design-components` | 주/보조 버튼, 카드, 칩, 말풍선(글루비+문구), 시트 헤더, 빈/오류/로딩 상태 |
| D2 | `feat/ios-v4-shell` | 탭 4개(홈/리포트/리뷰/설정), 로그인 화면 |
| D3 | `feat/ios-v4-home` | 홈: 날짜 이동, 하루 혈당 차트 + 기록 마커, 그래프 업로드 빈 상태, 음식/인슐린 시트 |
| D4 | `feat/ios-v4-food-record` | 촬영 화면, 음식 확인(맞나요? 흐름, 양 확인 시트, 상황 칩), kcal 제거 |
| D5 | `feat/ios-v4-insulin` | 인슐린 시트, 날짜·시간 선택 시트, 평소 인슐린(기기 저장) |
| D6 | `feat/ios-v4-reports` | 일간 타임라인(당시 혈당), 주간(지금 있는 숫자만) |
| D7 | `feat/ios-v4-settings` | 설정 목록, 혈당 가져오기, 로컬 알림(식사·하루 마무리) |
| D8 | `feat/ios-v4-review-hypo` | 리뷰 탭: 저혈당 처치 에피소드만(일일 리포트 응답 재사용), 빈 상태 |

D2+D3를 먼저 만들어 Figma와 비교한 뒤 나머지를 진행한다.

### B단계 — 백엔드가 먼저 필요한 것 (`docs/backend-api.md` 수정안부터)
- 음식 검색·자주 먹는 음식·직접 등록 (`food_catalog` 검색 + 사용자 음식 테이블)
- 대응 리뷰 목록/상세 (기간 조회, 직후·30·60·90분 값, 고혈당=인슐린 기준 에피소드, 비슷한 기록)
- 주간 범위 내 시간(70–180), 끼니별 건수, "먹지 않았어요" 기록
- 하루 마무리(다이어리 완료, 한마디, 연속 기록 칸)
- 프로필(별명, 평소 인슐린 제품)
